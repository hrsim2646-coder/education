# 관세법 법령 연계뷰 (웹앱)

**결과물**: `APP/관세법_법령연계_웹앱.html` (파일 1개로 동작, 인터넷 불필요 · 모바일은 카톡/드라이브로 전송해 열기)

## 구조
```
LAW/
 ├ BACKDATA/            ← 원문 PDF (법·령·칙·고시). 여기에 PDF를 넣는다
 ├ DATA/
 │   ├ snapshots/       ← 문서·시행일별 파싱 결과 보관(개정 비교의 기준, 자동 생성)
 │   ├ export/lawgraph.json  ← 후속 문제출제/논술/다른 웹앱용 원천 데이터
 │   ├ links_manual.json     ← 연계 선을 수동으로 추가/삭제
 │   ├ text_overrides.json   ← 띄어쓰기 수동 보정(글자가 달라지는 보정은 자동 거부)
 │   └ 검수필요_띄어쓰기.txt ← 줄바꿈 지점 띄어쓰기를 모델이 불확실하게 본 곳
 ├ APP/                 ← 완성 웹앱
 ├ tools/lawapp/        ← 빌드 코드 (lawparse.py 파서 / linker.py 연계추출 / build_app.py / app_template.html 화면)
 └ 웹앱_빌드.bat         ← 더블클릭하면 다시 빌드
```
(기존 `DRAFT/` 폴더의 1차 초안 3종과 `tools/`의 기존 스크립트는 그대로 두었습니다.)

## 업데이트 방법
1. **고시 추가**: 파일명에 `고시`(또는 훈령·예규·지침)가 들어간 PDF를 `BACKDATA`에 넣고 `웹앱_빌드.bat` 실행 → 4번째 `고시` 열이 생기고 “법 제○조 / 영 제○조 / 규칙 제○조” 인용을 따라 자동 연결됩니다.
2. **법령 개정**: 개정된 법·령·칙 PDF(파일명 끝 `(시행일YYYYMMDD)`)를 `BACKDATA`에 추가하고 빌드 → 직전 버전과 자동 비교해 조문별 **변경 전/후**(삭제=빨간 취소선, 추가=초록)가 `개정·자료` 탭과 해당 조문 카드(`개정 · 변경 전/후` 버튼)에 표시됩니다. 이전 버전은 `DATA/snapshots`에 남아 있어 옛 PDF를 지워도 이력이 유지됩니다.
3. **연계 보정**: 자동 추출이 틀린 곳은 `DATA/links_manual.json`의 `add`/`remove`에 `{"from":["law","100","1"],"to":["decree","118","1"],"ty":"d"}` 형식으로 적습니다. (`ty`: d=위임·시행, c=인용, p=벌칙)

## 원문 일치 원칙
- 본문은 PDF의 글자를 그대로 사용합니다(부칙 앞까지, 삭제 조문 포함). 빌드할 때마다 **PDF 본문(공백 제거)과 파싱 결과(공백 제거)가 글자 단위로 동일한지 대조**하고, 다르면 빌드가 중단됩니다.
- PDF는 줄이 바뀌는 지점의 띄어쓰기 정보를 담고 있지 않아, 그 지점의 공백만 문맥 모델로 복원합니다(검증용 분할 시험에서 위치당 약 98%). 불확실한 지점은 `검수필요_띄어쓰기.txt`로 따로 뽑습니다.
- 개정 태그(`<개정 …>`)·`[본조신설]` 등은 본문에서 분리해 카드 상단 태그/하단 주석으로 표시합니다.
- 정식 구축 시에는 국가법령정보센터 Open API(구조화 XML)를 쓰면 띄어쓰기 문제까지 사라집니다.

## 연계선 종류
| 선 | 의미 | 판정 |
|---|---|---|
| ━ 실선 | 위임·시행 | 하위법령 항 첫머리에서 “법 제○조(제○항)에 따라/의 규정에 의하여/에서 …”로 근거를 든 경우, 또는 상위 조문에 “대통령령/○○부령/고시로 정하는”이 있는 경우 |
| ╌ 파선 | 단순 인용 | 호·목 등에서 지나가며 언급한 경우 |
| ┈ 점선(빨강) | 벌칙 | 법 제11장 벌칙 조문이 같은 법의 위반 대상 조문을 인용한 경우 (역방향은 “←”로 표시) |
